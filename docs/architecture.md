# Архітектура Cryptonite

Cryptonite — бібліотека мовою C (C99), що складається з чотирьох основних шарів.
Кожен шар збирається окремою бібліотекою і залежить лише від шарів нижче.

```
┌─────────────────────────────────────────────┐
│  storage — ключові сховища PKCS#5/8/12      │
├─────────────────────────────────────────────┤
│  pkix — сертифікати, CRL, OCSP, TSP, CMS    │
├──────────────────────┬──────────────────────┤
│  cryptonite          │  asn1                │
│  криптографічне ядро │  ASN.1 runtime       │
├──────────────────────┴──────────────────────┤
│  pthread — сумісність потоків (Windows)     │
└─────────────────────────────────────────────┘
```

## Модулі

### `src/asn1` — ASN.1 runtime

Бібліотека кодування/декодування структур ASN.1 (BER/DER-подібні кодування),
заснована на runtime компілятора [asn1c](https://github.com/vlm/asn1c).
Містить базові типи (`INTEGER_t`, `OCTET_STRING_t`, `OBJECT_IDENTIFIER_t` тощо)
та механізми серіалізації. Використовується шарами `pkix` і `storage`.

**Код цього модуля переважно портований/згенерований — вручну його не редагують.**

### `src/cryptonite` — криптографічне ядро

Реалізації криптографічних алгоритмів без зовнішніх залежностей:

| Категорія | Файли | Алгоритми |
|-----------|-------|-----------|
| Хеш-функції | `dstu7564.h`, `gost34_311.h`, `sha1.h`, `sha2.h`, `md5.h` | «Купина», ГОСТ 34.311, SHA-1/2, MD5 |
| Блокові шифри | `dstu7624.h`, `gost28147.h`, `aes.h`, `des.h` | «Калина», «Магма», AES, DES/3DES |
| Підписи | `dstu4145.h`, `gost3410.h`, `ecdsa.h`, `dsa.h`, `rsa.h` | ДСТУ 4145, ГОСТ 34.310, ECDSA, DSA, RSA |
| MAC | `hmac.h` | HMAC над будь-яким хешем бібліотеки |
| Інфраструктура | `byte_array.h`, `prng.h`, `paddings.h`, `crypto_cache.h`, `cryptonite_errors.h` | базовий тип даних, ГПВЧ, доповнення, кеш, помилки |

Внутрішня математика (арифметика великих чисел, поля GF(p)/GF(2^m), операції
на еліптичних кривих) — у файлах `math_*_internal.c`, `word_internal.c`.
Файли з суфіксом `_internal` не входять у публічний API.

### `src/pkix` — інфраструктура відкритих ключів

Найбільший модуль. Складається з чотирьох підшарів:

- **`c/struct`** — ASN.1-структури PKI (сертифікат, CRL, CMS тощо),
  **автозгенеровані** компілятором asn1c зі схем ASN.1. Не редагуються вручну.
- **`c/api`** — робота з готовими об'єктами PKI: розбір, створення,
  читання полів, перевірка (`cert.h`, `crl.h`, `signed_data.h`, `oids.h`…).
- **`c/crypto`** — адаптери, що зв'язують PKI з криптоядром:
  `sign_adapter`, `verify_adapter`, `digest_adapter`, `cipher_adapter`,
  `dh_adapter`. Центральна фабрика адаптерів — `cryptonite_manager.h`.
- **`c/engine`** — високорівневі генератори: сформувати сертифікат,
  запит на сертифікацію, CMS-підпис, зашифровані дані, OCSP/TSP
  запити й відповіді (`*_engine.h`).

Типовий потік: **engine** будує об'єкт, використовуючи **адаптери** для
криптографії, результат — **struct**-об'єкт, який серіалізується в DER
через **api**.

### `src/storage` — сховища

Ключові контейнери: PKCS#5 (шифрування на паролі), PKCS#8 (контейнер
приватного ключа), PKCS#12 (файлове сховище ключів і сертифікатів),
а також сховище сертифікатів (`cert_store.h`).

### `src/pthread` — шар сумісності

Мінімальна реалізація підмножини pthread для Windows (мьютекси, потоки),
щоб основний код був однаковим на всіх платформах.

## Тестові модулі

| Модуль | Призначення |
|--------|-------------|
| `*Utest` | модульні тести (unit) |
| `cryptoniteAtest` | приймальні тести (acceptance) на тестових векторах стандартів |
| `cryptonitePtest` | тести продуктивності (performance) |
| `cryptoniteXtest` | розширені/крос-тести |
| `*TestUtils` | спільний код тестів |
| `cryptoniteExample`, `pkiExample` | демонстраційні програми |

## Наскрізні угоди

- **Дані** передаються через непрозорий тип `ByteArray` (`byte_array.h`);
  сирі `uint8_t*` у публічному API майже не з'являються.
- **Контексти** алгоритмів непрозорі: `XxxCtx *xxx_alloc(...)` →
  `xxx_init_*(...)` → робота → `xxx_free()`.
- **Помилки**: майже всі функції повертають `int`; `RET_OK` (0) — успіх,
  інші коди — за категоріями в `cryptonite_errors.h`, `pkix_errors.h`,
  `storage_errors.h`.
- **Володіння пам'яттю**: вихідні параметри `Xxx **out` — об'єкт створює
  функція, звільняє викликач відповідною `*_free()`.
- **Експорт символів**: макрос `CRYPTONITE_EXPORT` (задається при збірці).
